## 1. 日志无限增长修复

- **问题**：日志轮转只在启动时判断，长期挂机日志无限膨胀；`pet-fs-*` 临时探针目录已累积 178 个。
- **修法**：
  - Electron 侧新建 `logRotation.ts`（20MB 上限、保留 3 份备份），`log()` 写入前先记账轮转。
  - Python 侧 `main.py` 加 `_SizeRotatingFileHandler`（Windows 文件占用 → close→rotate→reopen）。
  - `fullscreenWatcher.ts` 导出 `sweepStaleProbeDirs()`，清理超过 1 小时的 `pet-fs-*` 目录。
- **验证**：`tools/check-log-rotation.py` 6 项断言 + test:main 相关 13 项全过。

## 2. 语音开关抽出（菜单项）

- 「语音播报」做成与「麦克风」「允许看屏幕」同款开关，位置在其上方；读取 设置→语音 的 TTS 配置（`providers.tts.enabled`），开启后文字回复转语音。
- `config.py` 默认值补 `tts.enabled: True`；`voice.py` 说话前实时读取该配置；`tools/check-tts-gate.py` 5 条规则验证（enabled=False 全静音、缺键不静音、Mock 引擎静音、被打断静音等）。

## 3. 「显示气泡」单向门修复

- **现象**：气泡显示中 → 菜单隐藏 → 再点「显示气泡」不出来。
- **根因**：「开」的时候没有内容可弹，什么都不做——对刚被藏起来的气泡是错的。
- **修法**：`sendToBubble()` 发送前缓存 `lastBubbleMessage`；「显示」时重放（重新定位 + 重发消息，存在时间重新起算）。

## 4. 视觉修补三连（主题化不彻底类）

| 问题 | 根因 | 修法 |
|---|---|---|
| 深色主题点输入框变白底白字 | `chat.css` `.input:focus { background: #ffffff }` 写死 | 新增 `--input-focus-bg` 变量（深色 #343847），两主题分别定义 |
| 状态条四周灰圈 | ① `statusWindow.ts` 漏 `thickFrame: false`（DWM 边框露出）② 胶囊 box-shadow | 补 thickFrame:false + 整个移除阴影 |
| 对话条四角灰 | `--bg` 半透明 + backdrop-filter 在透明窗口里画出灰层 | 底色改不透明、删 backdrop-filter、阴影收敛到 0.10 |

- **教训**：凡 `transparent: true` 的窗口，半透明底 / backdrop-filter / 大面积 box-shadow 实机都会变灰圈；走 `data-theme` 换肤的文件出现字面色值就是隐患（今天连修 3 处同款病）。
- 另：状态条文字加粗 `font-weight: 700`（微软雅黑无 600 档，600 渲染等同 700）。

## 5. 边缘探头形态随抓取点变（有备份）

- **现象**：拖头部到屏幕边缘 vs 拖中部到边缘，探头姿态完全不同。
- **根因**（日志实锤）：横向吸附早已固定且生效；**纵向 `rawY = current.y` 完全跟随松手位置**，散布 143px，倾斜 45° 被屏幕裁切后就是两种结果。
- **修法**：`peekWindowBounds` 加可选 `cursor` 参数——左右探头时立绘中心 Y 吸附到光标松手 Y（夹屏幕内），上下对称处理 X。光标与抓哪里无关 → 结果一致。仅 drag-end 传光标，滑杆重排等重入路径保持旧行为。
- **备份**：`F:\ai项目\.backup\peek-snap-20261016\`（petLayout.ts + petWindow.ts 原件，可整体覆盖回滚）。
- **验证**：test-main 新增 5 条断言（含"换抓取点立绘中心不变"）。

## 6. 搜索架构盘点与「空壳」诊断

- **现状架构**：主路径 MCP（websearch-mcp.exe，~1.5s）→ 退路 1 自抓 HTML（Bing/360）→ 退路 2 隐藏浏览器兜底（默认关）。
- **「空壳」不是长度截断**（截断只在超长时砍尾），真因：① 通用引擎分词劣化（"二重螺旋"命中"二"字汉典，相关性 0.009）；② MCP 默认不抓正文只给摘要；③ B 站等 JS 站抓回来就是壳。
- **关键发现**：项目里已有专用 `bilibili_search` 工具（站内接口带播放量），实测直接命中用户想要的版本前瞻内容——模型只走 web_search 才踩空壳。

## 7. free-search-mcp 评估与三选一搜索模式（大项）

- **评估对象**：github.com/sweetcornna/free-search-mcp v0.13.1（MIT，68 个免 key 来源，支持 `--transport streamable-http`，与现有手写 MCP 客户端直接兼容）。
- **A/B 实测（国内直连，VPN 关闭）**：

| 查询 | free-search | websearch-mcp | 自抓 HTML |
|---|---|---|---|
| b站 热门视频 | 10.1s / 2723 字 / 命中 B站热门页真实链接 | 1.5s / 2 条官网首页 | 20.4s / 全垃圾 |
| 二重螺旋 新版本 | 20.1s / 3229 字 / 命中官方 10月28日公测公告 | 1.4s / "二"字汉典 | 20.3s / "二"字字典 |

- **结论**：命中质量碾压，代价 10~20 秒。
- **用户拍板：三选一 radio 模式**：精准搜索（free-search，约 10~20 秒）/ 快速搜索（websearch-mcp，约 2 秒）/ 关闭。真源 `tools.web_search_mode`（accurate/fast/off）+ 布尔影子键兼容老配置。
- **实现**：
  - Python：`mcp_search.py` 加 `search_free()`（写死挑 "search" 工具——names[0] 字母序是 cache_search，永远查空缓存）+ `ensure_free_running()`（握手不通自动拉起服务器，实测杀掉后自动重启成功）；`tools.py` 按模式分流 + accurate 失败回退 fast 链路。
  - Electron：菜单三选一 radio，persona.yaml 落盘热更新。
  - 安装坑：venv 必须放 ASCII 路径（中文路径 pyvenv.cfg 读不到）；selectolax 必须降级 <1.0。
- **踩坑两连**：
  1. action 前缀写成 `websearch-mode:` 被 camelCase 转成 `websearchMode`（小写 s），与处理器 `webSearchMode` 对不上 → 子菜单整体置灰。action 的单词边界必须与处理器驼峰边界一一对应 → 改 `web-search-mode:`。
  2. 两层嵌套子菜单点不开（自绘菜单展开交互只为一层设计）→ 按用户指示把「联网搜索」提到一级菜单，加 globe 地球图标。

## 8. 状态栏四档状态机（今天最后一项）

- **问题**：状态条每个事件源各写各的——回复时显示"说话"（还没说）、工具结束直接跳"在线"（回合没完）、`pet.thinking` 事件从未被消费 → 联网搜索时变来变去。
- **修法**：集中状态机 + `refreshActivityStatus()` 单一刷新入口，事件只改状态变量：

| 状态 | 触发 | 灯色 |
|---|---|---|
| 空闲 | 默认 / voice idle / 90s 看门狗 | 绿 #34c759 |
| 思考中 | pet.thinking / pet.say.start | 紫 #bf7af0（呼吸） |
| 联网搜索中 | pet.tool start（计数制，期间盖过思考，end 不跳在线） | 蓝 #2f86ed |
| 语音准备中 | pet.say.end(done) 且语音开启且文字回复已得到 | 青 #32ade6（呼吸） |
| 说话 | voice.state speaking | 琥珀 #ffb300 |
| 异常 | TTS 合成失败 → 显示 `TTS 合成失败：<原因>`，下一回合思考自然带出 | 红 |

- **语音准备中语义（用户三轮细化定稿）**：进入 = 语音开启 + 文字回复已得到；退出仅两条路——语音开始播放 → 说话态，或 TTS 失败 → 异常态。进入条件**不看** ttsHealthy（否则失败过一次就永远进不了准备中）。
- 跳变记日志 `[状态条] a -> b`；90s 看门狗兜 end 事件丢失。
