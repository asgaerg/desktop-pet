- **重建中踩的坑**：
  1. `async def` 在 ast 里是 **AsyncFunctionDef**，不是 FunctionDef——抠 `_on_pet_say_end_speak` 第一次扑空；
  2. 测试里"先建占位 FileHandler 再替换"且不 close——Windows 上占着句柄，轮转的 `path.replace()` 会静默失败；
  3. 轮转的磁盘语义：emit 里先 `close()`（缓冲此时才落盘）再查 `st_size`，**测试的 max_bytes 必须与行宽对齐**（105 字节/行、max=208 → 每 2 行稳定滚一次）；
  4. 沙箱 `ELECTRON_RUN_AS_NODE=1` 会让 electron 退化成纯 Node；GPU 进程在沙箱崩（0xC0000005）→ 离屏截图要加 `--disable-gpu --no-sandbox`。
- **验证**：check-log-rotation 12 断言 / check-tts-gate 5 规则全过；probe-ab `--only scrape` 复现"二重螺旋→'二'字汉典"的历史结论。

## 2. 搜索拉起时弹黑框修复

- **根因**：`mcp_search.py` 的 `_detached_kwargs` 把 `DETACHED_PROCESS` 和 `CREATE_NO_WINDOW` **同时**用——MSDN 明说互斥、组合行为未定义，实测就是控制台照样弹（free-search-mcp.exe 黑框）。
- **修法**：去掉 `DETACHED_PROCESS`，只留 `CREATE_NO_WINDOW + CREATE_NEW_PROCESS_GROUP`。⚠️ **别再把它俩加回去**。

### 4.2 起点信号（说话中什么时候亮）

- **渲染层说了算**：`app.js` 收到 `pet:voice-audio` 要开播时 → `window.pet.notifyVoiceSpeaking()`（新 preload API）→ IPC `pet:voice-speaking` → 主进程**无条件** `voiceSpeaking=true + turnThinking=false + setStatus('说话中')`。
- ❌ 两个被否掉的方案（别走回头路）：`voice.state speaking` 是 Python 在 `pet.say.start`（**文字阶段**）发的，不是音频在播；主进程转发点（binary drain）的钩子依赖转发时刻的状态条件，时序会漏（实测音频在播还挂思考中）。
- 主进程 binary drain 里的钩子保留为兜底 + 诊断日志（`音频帧到达但状态不在思考/说话`）。

### 4.3 终点信号（什么时候回空闲）——双保险 + 看门狗

- `voice-io.js` 播放结束改**幂等 report()**：`onended` 和 **`setTimeout(buffer.duration*1000 + 250)`**（音频自带精确时长）谁先到都算数——实测 `onended` 有概率不触发（main.log 实锤：起点两条都有、终点始终没来）。
- 渲染层 report → `notifyVoicePlayed()` → IPC `pet:voice-played` → 主进程 `if (voiceSpeaking) clearActivityStatus()`。`source.stop()`（打断）也触发 onended，同样回空闲。
- 90 秒看门狗条件加 `voiceSpeaking`：终点信号全丢时最多挂 90 秒强制回空闲。

### 4.4 🔴 真凶（四轮迭代后才抓到，最重要的一条）

- **`audio` 是懒创建单例，但麦克风预热 `warmUpVoice()`（开机即跑）和设置页枚举麦克风也会 `if (!audio) audio = new VoiceIO()`——不带 onPlaybackEnded 回调**。宠物语音到达时 `if (!audio)` 为假 → 回调永远挂不上 → 播完没有终点信号。
- **修法**：`pet:voice-audio` 处理器里**每次播放前无条件重挂** `audio.onPlaybackEnded`（幂等）。⚠️ 不要把它塞回 `if (!audio) {}` 分支。
- **教训**：懒创建单例 + "在创建点挂回调" = 回调可能永远挂不上；回调要挂在**使用点**。且"自己启动测试"要复现**使用方的接线方式**（VoiceIO 机制单测是过的，bug 在接线）。
- **自测工具**：`tools/test-voice-end.mjs`（`npm run test:voice-end`）——真实 Electron 离屏窗口 + http 源加载真 voice-io.js，三场景（自然播完 @1212ms / 打断即报 / 连播 2 次终点）全过。

## 5. 气泡排版（紧凑化 + 段落化 + 宽度分档 + 段间距可调）

- **紧凑化**：行高 1.55→**1.45**、padding 8px13px→**7px12px**。
- **段落化渲染**（用户要「段落之间留一点点间距」——纯文本 pre-line 做不到半行间距）：`bubble.js` 加 `bubbleRaw` 缓冲（原始全文原样保留）+ `renderParagraphs()`——按 `\n{2,}` 切段、每段一个 `.para`，段内单 `\n` 交给 pre-line；流式追加**整段重排**（\n 可能跨块到达）。CSS：`.bubble-text .para + .para { margin-top: var(--para-gap, 4px) }`。
  - ⚠️ 流式光标 `::after` 挪到了 `.para:last-child`——挂容器上会掉到段落块之外另起一行。
  - ⚠️ `hasContent` / `syncEmptyMark` / `naturalBubbleWidth` 读 `textContent` 的口径不变（div 拼接仍是纯文本）。
- **宽度分档**（`desiredWindowWidth`）：`>100` 字维持上限 **520**；`≤100` 字上限 **300**（用户定的数值）。宽度由渲染层单向算好、主进程照用——**不要动主进程推导**，会回到测量闭环（10-05 踩过的坑）。
- **段间距进设置页**：设置 → 宠物 → 「气泡段间距」（数字输入框 0~24px，默认 4，紧挨「文字弹窗存在时间」）。链路照 bubbleLinger 的完整套路：settingsStore 新增 `bubbleParaGap`（clamp 0~24 + DEFAULTS + parse + patch merge）→ `settings:bubble-para-gap` / `settings:set-bubble-para-gap` 两个 IPC → **双通道生效**：① 改完立刻 `bubbleWindow.setParaGap()` 推 `bubble:message {kind:'config'}`（渲染层只写 CSS 变量 `--para-gap`，不动显示状态）；② paraGap 同时随每条 bubble:message 下发（与 lingerMs 同通道）。落盘记住。
