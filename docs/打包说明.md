## 二、目录布局（和代码里的三个根一一对应）

代码里把"一个根"拆成了三个（`apps/desktop/src/main/index.ts` 顶部）：

| 常量 | 开发态 | 打包态 | 放什么 |
|---|---|---|---|
| `APP_ROOT` | 仓库根 | `resources/`（只读） | renderer、config 模板、pet.exe、词典 |
| `DATA_DIR` | `apps/desktop/pet-data` | `%APPDATA%\DesktopPet\pet-data` | 日志、记忆库、备份、模型 |
| `CONFIG_ROOT` | 仓库根 | `%APPDATA%\DesktopPet` | `config/persona.yaml`（会被写） |

**为什么配置必须放 `%APPDATA%`**：程序运行时会写 `persona.yaml`（模块开关、push-to-talk、
activity）。放在 `Program Files` 里没有写权限，表现是"设置改了、重启又变回去"。

安装后（默认装到 `%LOCALAPPDATA%\Programs\DesktopPet`）：

```
<安装目录>/
  DesktopPet.exe
  Uninstall DesktopPet.exe
  resources/
    app.asar                          <- dist（主进程/预加载）+ src/renderer（53MB 立绘素材）
    config/                           <- 只读模板，首启复制到 %APPDATA%
    pet/pet.exe                       <- PyInstaller 冻结的 sidecar（273 MB）
    pet/websearch-mcp.exe             <- 联网搜索后端
    apps/desktop/tools/*.ps1          <- 全屏检测 / SAPI 语音
    apps/desktop/pet-data/vendor/     <- cppjieba 词典（只读）
    apps/desktop/pet-data/models/     <- bge-small-zh-v1.5 语义嵌入（91MB）
    apps/desktop/pet-data/asr-models/ <- 只有离线版有（1.55GB）
```

### 3. 出包

### 3.5 代码签名（2026-10-30 起）

**证书**：自签名，`CN=Tianyi DesktopPet (Self-Signed), O=Tianyi, C=CN`，
5 年有效（到 2031-10-30）。文件在 `build/signing/`（**不进 git**）。

#### 🔴 顺序很重要：先签 `win-unpacked`，再打 zip

`electron-builder` 的 NSIS 安装包是**一步生成完**的，签它只要在生成后做。
但**绿色包是从 `release/win-unpacked` 压出来的** —— 如果先压 zip 再签名，
zip 里那些 exe 就还是未签名的。

正确顺序：

```powershell
# ① 出包（生成 release/win-unpacked 和 NSIS 安装包）
npm run package:online

# ② 签 win-unpacked 里的 exe —— 必须在打 zip 之前
#    ⚠️ 用 pwsh 直接跑 signtool，不要从 Python 子进程调（见下面的坑）
```

```powershell
$st = 'C:\Program Files (x86)\Windows Kits\10\bin\10.0.19041.0\x64\signtool.exe'
$pfx = 'F:\ai\build\signing\desktoppet-selfsigned.pfx'
Get-ChildItem release\win-unpacked -Filter *.exe -Recurse |
  ForEach-Object {
    & $st sign /f $pfx /p 'desktoppet' /fd sha256 `
        /tr 'http://timestamp.digicert.com' /td sha256 $_.FullName
  }

# ③ 签 NSIS 安装包
& $st sign /f $pfx /p 'desktoppet' /fd sha256 `
    /tr 'http://timestamp.digicert.com' /td sha256 `
    release\DesktopPet-<ver>-online-setup.exe

# ④ 现在才压绿色包
tar -a -c -f release\portable\DesktopPet-<ver>-online-portable.zip -C release\win-unpacked .
```

#### 验证

```powershell
python tools/make-signing-cert.py status
# 期望每个包显示 Valid
```

> **`Valid` 的前提是本机装了根证书**。没装会显示 `UnknownError` ——
> 那不代表签名坏了，只代表"这台机器还不信任这个根"。
> 装证书：右键 `build/signing/发给朋友/install-cert.ps1` →「使用 PowerShell 运行」。

#### 🔴 两个必须知道的坑

**① 从 Python 子进程**创建证书/读 PFX 私钥**会失败**

实测（2026-10-30），同一段脚本、同一个 `powershell.exe`：

```
pwsh 工具直接执行      -> ✅ OK
python subprocess      -> ❌ CertEnroll::... 0x80090010 (NTE_PERM)
signtool 从 python 调  -> ❌ Store::ImportCertObject() failed (-2146893808)
```

`NTE_PERM` = 调用者无权访问密钥容器。换过 `-Command` / `-File` /
`-EncodedCommand`、换过工作目录、换过 `APPDATA` 环境变量、试过 `schtasks`
委托 —— **全部失败**。这是当前执行环境对子进程的限制。

所以：**生成证书和签名都要用 pwsh 直接执行**（或用户手动开 PowerShell 跑）。
`tools/make-signing-cert.py` 的 `create` 会检测到这一点并打印可直接粘贴的命令。

**② 装根证书会弹一次系统「安全警告」，必须手动点「是」**

任何程序往「受信任的根证书颁发机构」写证书，Windows 都会强制确认，
**无法绕过也不该绕过**。用 `X509Store` 写入时会看到名为
`Security Warning` 的窗口，点「是」后签名状态立刻从 `UnknownError`
变成 `Valid`。

#### 这件事解决了什么、没解决什么

| 场景 | 结果 |
|---|---|
| 本机（装了根证书） | ✅ 双击安装包无任何提示 |
| 朋友（照 `说明.txt` 装一次） | ✅ 之后所有版本都无提示，5 年内有效 |
| 陌生人首次下载 | ❌ 仍弹「未知发布者」，和没签名一样 |

自签名的根不在微软信任列表里，所以对陌生人无效。要彻底解决只能买
**EV 代码签名证书**（约 2500~4000 元/年 + 企业资质 + 硬件 U 盾）。

**替代方案**：主推**绿色包**（`*-portable.zip`）。zip 不走安装器那一轮检查，
实测是不买证书时最不容易被拦的分发方式 —— 这也是 README 现在把绿色包
放在第一位的原因。

## 五、本机环境上的两个坑（换机器不一定会遇到）

### ① `%APPDATA%\Roaming` 不可写

Electron 和 Python 都报 `WinError 5 拒绝访问`。打包版一启动就因为建不了 userData 直接退出。

→ 代码里支持 `PET_USER_DATA` 覆盖 userData（便携模式），测试时用：

```powershell
$env:PET_USER_DATA = 'F:\ai项目\_install-data'
```

真实用户不设它，行为不变（`%APPDATA%\DesktopPet`）。

### ② hosts 把 github.com 指到 127.0.0.1

```
127.0.0.1 github.com            #S302（某个网络工具的屏蔽项）
```

electron-builder 下载 NSIS / winCodeSign 走 Node 直连 → 命中 hosts → `ECONNREFUSED 127.0.0.1:443`。
开 VPN 也没用（VPN 代理在 10809，Node 不读系统代理）。

→ 给 builder 进程显式设代理即可：

```powershell
$env:HTTPS_PROXY='http://127.0.0.1:10809'
$env:HTTP_PROXY='http://127.0.0.1:10809'
npm run package:online
```

下载一次后就进缓存（`%LOCALAPPDATA%\electron-builder\Cache`），之后断网也能出包。

## 六、离线版 EBUSY 的兜底：`--prepackaged`

NSIS 复制 1.55GB 模型时偶发：

```
⨯ EBUSY: resource busy or locked, copyfile ... websearch-mcp.exe / model.onnx
```

先按顺序试这几步：

```
1. Get-Process python,pet,websearch-mcp,DesktopPet | Stop-Process -Force
2. 删掉 release-offline 再打（残留文件会被杀软/索引器短暂占用）
3. 还不行就走 --prepackaged：
   · 用 online 配置先出绿色目录（它只用几百 MB，不会撞锁）
       npx electron-builder --win --dir --config electron-builder.online.yml -c.directories.output=../../release-offline
   · robocopy 把模型补进去
   · 再从现成目录直接压安装包
       npx electron-builder --win nsis --prepackaged F:\ai项目\release-offline\win-unpacked ^
           --config electron-builder.offline.yml -c.directories.output=../../release-offline
```

## 六之二、`release\win-unpacked`：留着，但别当"最新包"用

出包之后 `release\win-unpacked\` 会留着（在线版 744 MB）。**不要删**，它是三件事的底子：

```
① 绿色包：tar 一下就完事
     tar -a -c -f release\portable\DesktopPet-<ver>-online-portable.zip -C release\win-unpacked .
② 只想换壳重封 NSIS（不想再跑一次 --dir）：
     npx electron-builder --win nsis --prepackaged release\win-unpacked --config electron-builder.online.yml
③ 临时验证：双击里面的 DesktopPet.exe，跑的就是"安装包里的那份东西"
```

### ⚠️ 坑：它是上一次构建的快照

`release\win-unpacked` 里装的是**上一次 `--dir` 时的代码**。改完源码直接拿它封包，
出来的安装包还是旧的 —— 症状是"明明改了却没生效"，特别像打包失败。

改代码后**必须**比一次时间（这是唯一可靠的判据）：

```powershell
Get-Item release\win-unpacked\resources\app.asar, apps\desktop\dist\main.cjs |
    Select-Object Name, LastWriteTime
```

`app.asar` 比 `main.cjs` 旧 = 这个目录已经过期，先跑一次 `--dir` 覆盖：

```powershell
npx electron-builder --win --dir --config electron-builder.online.yml
```

2026-10-19 就是差点拿 10-18 的 `win-unpacked` 封出旧包，一比 `app.asar` 时间才发现。

## 七、踩过的坑（按重要性）

```
① PROJECT_ROOT 用了 91 处
   path.resolve(DIST_DIR,'..','..','..') 在 asar 里算不出仓库根：
   读不到 config（静默用内置默认值）、写不进配置、pet-data 全丢。
   → 拆成 APP_ROOT / DATA_DIR / CONFIG_ROOT

② brain 里 5 处自己拼 parents[3]
   gateway / embedding_local / mcp_search / main.py（日志兜底）
   冻结成 exe 后 parents[3] 是 _internal，全错。
   → 新建 pet/paths.py，读环境变量 PET_PROJECT_ROOT / PET_DATA_DIR

③ userData 目录名是 "Electron"
   package.json 的 name 是 @pet/desktop，electron-builder 没写 productName，
   于是 app.getPath('userData') = %APPDATA%\Electron（和别的 Electron 应用混住）。
   → 打包态 `app.setName('DesktopPet')`，必须在算 DATA_DIR 之前调

④ 模型放 resources 里是只读的
   faster-whisper 会往 asr-models/.locks 写锁；写失败就当"没下载过"，
   断网时表现为"本地识别用不了"。
   → 首次启动复制到 DATA_DIR（ASR 异步、嵌入模型同步）

⑤ 全屏检测脚本路径只按 dist/cwd 推理
   打包后每秒刷一行 "找不到 tools/probe-fullscreen.ps1"。
   → resolveProbeScript() 增加 process.resourcesPath 候选

⑥ @pet/protocol 是 workspace:*，builder 遍历 dependencies 时直接报错
   → 它已经被 esbuild 内联进 dist/main.cjs，挪到 devDependencies 即可
   ⚠️ 副作用：npm install 会删掉 apps/desktop/node_modules/@pet/protocol 这个链接，
      删了类型检查就报 TS2307。恢复：mklink /J

⑦ 密钥扫描把二进制里的巧合字节当成密钥（vulkan-1.dll、nb.pak）
   → 扫描器跳过含 NUL 的文件（真密钥只在文本里）

⑧ 记忆库被建到安装目录里（打包后才暴露）
   store.default_db_path 用 project_root 拼路径，打包态那是只读的 resources/。
   → 改成 paths.data_dir()；升级/卸载才不会连记忆一起删

⑨ 安装包放在含中文的路径里 -> NSIS 静默失败
   实测矩阵：安装包在 F:\ai项目\release、目标 C:\Temp -> ❌；
             同一份文件挪到 F:\temp 或 C:\Temp -> ✅。
   → 发布说明里要写"先复制到英文路径再装"；测试脚本也别从仓库目录直接跑

⑩ 自定义 nsis.uninstallerIcon 会往安装目录写 .ico
   桌面 / OneDrive 这类被同步的目录更容易失败。
   → 只设 win.icon，别设 nsis 的两个图标

⑪ 整目录照搬 = 把历史垃圾一起发货
   pet-data/vendor 里躺着 10-06 的旧记忆库；tools 里有 .bak。
   → 一律显式列清单或加 filter，并用 check-pack-privacy.py 兜底

⑫ release\win-unpacked 是上一次构建的快照
   改完代码直接 --prepackaged 它，封出来还是旧代码（看着像"打包没生效"）。
   → 封包前比 app.asar 与 dist/main.cjs 的时间；旧了就重跑 --dir
```

## 八、改 Python 代码之后

```
1. npm run package:sidecar     # 重新冻结（约 1 分钟）
2. npm run build               # 只改 TS 时可跳过 1
3. npm run package:online      # 或 package:offline
```
