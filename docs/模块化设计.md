## 三、模块化要解决的三个问题

```
① 能关：关掉后**代码不再被执行**，不只是界面隐藏
   （否则语音模块关了，后台还在加载 3.7 GB 模型、还在监听麦克风）
② 能换：换掉后**别人实现的版本能接上**（接口稳定，不依赖具体类）
③ 一致：前端隐藏 + 后端拒绝，**两边同时生效**，不能靠前端"藏着不点"
```

## 四、设计

### 4.1 单一真源：`config/modules.yaml`

```yaml
# 每个模块一行；enabled 为 false 时后端不启动、前端不显示入口
modules:
  memory:       { enabled: true }
  persona:      { enabled: true }
  chat:         { enabled: true }
  voice:        { enabled: false, reason: "省 3.7 GB 模型，纯文字模式" }
  subjectivity: { enabled: true }
  autonomy:     { enabled: true }
  monologue:    { enabled: true, depends: [autonomy] }
  screen:       { enabled: false, depends: [autonomy] }   # 还要 providers.vision.enabled
  search:       { enabled: true, depends: [chat] }
```

依赖规则：
- `depends` 里任一模块关闭 → 本模块自动关闭，并在日志/界面说明原因（**不能静默**）
- `core.*` 不在此表里（不可关）

### 4.2 后端：`pet/modules.py`（新增，约 150 行）

```python
class Module:
    id: str
    depends: tuple[str, ...]
    start: Callable[[Gateway], Awaitable[None]] | None   # 起后台任务（如 autosnap 循环）
    stop:  Callable[[Gateway], Awaitable[None]] | None   # 收尾（关模型、停监听）

class ModuleRegistry:
    def enabled(self, mid: str) -> bool          # 含依赖的传递闭包
    def disabled_reason(self, mid: str) -> str   # "依赖 autonomy 未启用"
    async def apply(self, states: dict[str, bool]) # 热切换：停旧 -> 起新
```

网关里所有入口先过一道闸（示例）：

```python
if not self.modules.enabled("screen"):
    return  # 连事件都不订阅
```

**关键点：闸门放在"订阅"这一层，不是放在"处理"这一层。**
关掉 `autonomy` 就 `bus.unsubscribe("autonomy.tick")`，而不是让它继续每秒算一遍再丢弃。

### 4.3 协议：新增两个消息 + ready 里带状态

```ts
// 客户端 -> brain
{ type: "modules.query" }
{ type: "modules.set", patch: { voice: false, screen: true } }

// brain -> 客户端
{ type: "modules.state", modules: { chat: true, voice: false, ... },
  reasons: { voice: "用户关闭" }, requestId: "..." }

// 现有 ready 消息里加一个字段
{ type: "ready", ..., modules: { ... } }
```

### 4.4 前端：`window.__MODULES__` + 统一隐藏规则

```js
// 预加载注入（启动时由 main 从 ready.modules 写入）
const M = window.__MODULES__;
document.querySelectorAll('[data-module]').forEach((el) => {
  if (!M[el.dataset.module]) el.hidden = true;   // 入口消失
});
```

- 设置页新增「模块」标签：每个模块一行开关 + 关闭原因
- 关掉 `voice` → 麦克风按钮、语音设置整段消失
- 关掉 `memory` → 记忆窗口关掉、菜单项消失、`memory.query` 直接被后端拒绝
- **双层防护**：前端只负责"看不见"，后端负责"调不通"

### 4.5 替换：模块接口而不是模块实现

每个模块对外只暴露**能力**（capability），网关拿到的是能力对象：

```python
class MemoryCapability(Protocol):
    def remember(self, role: str, text: str, *, image: bytes | None = None) -> None: ...
    def recall(self, query: str, limit: int) -> list[dict]: ...

class VoiceCapability(Protocol):
    async def transcribe(self, pcm: bytes) -> str: ...
    async def speak(self, text: str) -> None: ...
```

换实现 = 换一个满足 Protocol 的类，不动调用方（例如以后把 `voice.py` 换成云端 ASR）。

## 五、分四步落地（每步都能独立收工）

### 第一步：登记 + 开关（不拆代码，先能关）

```
· 新增 config/modules.yaml（默认全开，除 voice/screen 保持现状）
· 新增 pet/modules.py（Registry + 依赖闭包 + 拒绝日志）
· gateway 里 9 个模块的"订阅/启动"位置加闸门
· 协议加 modules.query/set + ready.modules
· 设置页加「模块」标签（只读展示 + 开关）
验收：关掉 search -> 界面入口消失 + 日志「search 未启用」+ 工具调用被拒
```

### 第二步：把"启动即加载"改成"按需加载"

```
· voice：模型只在第一次语音输入时加载（现在启动就加载 3.7 GB 的思路要改掉）
· memory：DB 连接延迟到第一次读写
· screen：视觉模型懒加载
验收：全关状态下启动时间 < 3 秒、内存 < 200 MB
```

### 第三步：能力接口化（为"换"做准备）

```
· 每个模块抽出 Protocol（memory / voice / chat / screen）
· 网关只依赖 Protocol，不再 `from .voice import VoiceService`
· selftest 增加：用假实现替换每个模块，跑通一轮对话
```

### 第四步：第三方模块接入（可选，看你要不要）

```
· 模块目录约定 apps/brain/pet/modules/<id>/__init__.py
· 每个模块自带 module.yaml（id/name/requires/config schema）
· 启动时自动发现（不认识的模块不影响主程序）
```

## 六、风险与边界

```
· 不要在"第一步"就动代码结构 —— 先用开关证明"能关"，再谈"好换"；
  一上来就重构 32,000 行 Python 必然翻车。
· 关掉的模块**不能悄悄失败**：所有拒绝都要有日志 + 界面说明（用户的教训：
  「日志和事实不符比没日志更坏」）。
· 凭证与权限不进模块表：api key 永远在 credentials.json，截图/麦克风权限
  永远由用户显式打开（模块开关 ≠ 权限开关，两者是 AND 关系）。
· 状态栏、联网搜索界面是别人负责，本设计只登记、不改。
```

## 八、三处能力可切换：大脑 / 语音识别 / 语音合成（2026-10-18）

用户要求（原话）：

```
「大脑api、语音识别、文字转语音这三个目前要都可以用本地模型替代，
  不是让你找，我是说留好接口，做好切换方式，
  模块化是为了不用本地大模型选着云端api之后，让用户重启程序，
  重启后的程序启动更快占用性能更少，就不必每次都带着大模型跑着启动程序。」
```

### 8.1 现状盘点（改之前）

| 能力 | 接口 | 切换方式 | 现状 |
|---|---|---|---|
| 语音识别 | `AsrEngine` Protocol（voice.py:448） | `providers.asr.provider` = `local` / `cloud` / `mock` | ✅ 已可切换，且**只有选 local 才构造 `LocalAsrEngine`** |
| 语音合成 | `TtsEngine` Protocol（voice.py:460） | `providers.tts.provider` = `edge` / `openai` / `sapi` / `mock` | ✅ 已可切换 |
| 大脑 | `Brain` 基类 + `build_brain` 注册表 | `providers.brain.provider` = `openai` / `mock`，厂商在 `named` 里切 | ⚠️ **只能云端**：没有密钥时 `_validate()` 直接抛错 |

也就是说：ASR/TTS 的"可切换 + 按需加载"**本来就是对的**，真正缺的是两件事：

```
① 大脑接不了本地服务（Ollama / llama.cpp / vLLM 都不需要密钥）
② 没有任何地方能证明"这次启动到底加载了什么" —— 只看配置不算数
```

### 8.2 改了什么

**① 大脑支持本地端点（免密钥）** —— `brains/openai_compat.py`

```python
local = _is_local_url(self.base_url)      # 127.0.0.1 / localhost / ::1 / 0.0.0.0
self.api_key = config.api_key() or ("local" if local else "")
self.is_local = local
...
if not self.api_key and not self.is_local:
    raise ValueError("未找到密钥…")        # 云端仍严格要求密钥
```

于是本地大脑只需要在 `providers.brain.named` 加一项：

```yaml
named:
  ollama:
    base_url: http://127.0.0.1:11434/v1
    model: qwen2.5:7b
    # 不需要 api_key（本地服务不校验）
active: ollama
```

**② 启动时打一行"能力报告"** —— `gateway._log_capability_report()`

```
能力报告：大脑=云端（deepseek-flash） 语音识别=本地 语音合成=云端 大模型=会加载（本地 ASR）
```

这行是验证用户核心诉求的唯一凭据：**选云端时就该显示"不加载"**。
（教训：日志和事实不符比没日志更坏 —— 所以这行必须由**实际构造出的引擎**推出，
不能由配置推算。）

### 8.3 为什么"选云端 = 不加载大模型"能成立

```
build_voice_pipeline() 里是 if/elif 分支：
   provider == "local"  -> LocalAsrEngine(...)   ← 只有这一支才 import faster_whisper
   provider in ("openai","cloud") -> OpenAIAsrEngine(...)
   provider == "mock"   -> MockAsrEngine()
所以选云端时，本地模型的 **Python 模块根本不会被 import**，权重文件也不会被映射。
```

`asr-models`（3.7 GB）在这个分支下不会被打开 —— 实测该目录最新修改时间仍是
`2026-10-08 16:26:56`（云端模式跑了多次没变过）。

### 8.4 切换方式（用户视角）

```
设置 → 语音
  语音识别方式：本地大模型（离线） / 云端 API
    本地  -> 加载 large-v3-turbo（1.6 GB 显存），启动更慢
    云端  -> 不加载任何本地模型，启动更快、显存 0
  文字转语音：edge-tts（免费在线）/ 云端 CosyVoice / 系统 SAPI

设置 → 大脑 API
  提供商：DeepSeek / 硅基流动 / （本地：在 persona.yaml 的 named 里加一项）
```

> 界面上的大脑"运行位置"下拉还没做（当前靠 `named` + `active` 切换）。
> 下一步如果要放进设置页，就是在「大脑 API」标签里加一个 select，
> 选项 = `named` 的键 + "本地（127.0.0.1:11434）"。

### 8.5 还没做的（下一轮）

```
· 设置页「大脑 API」加"运行位置"下拉（本地/云端）+ 本地 base_url 输入
· 语音模型**真正懒加载**：现在选 local 就在构建管线时加载；可改成首次说话才加载
· 启动耗时/内存的**自动化基线**（这轮测量脚本没跑稳，不作数）
```

### 8.6 这轮的踩坑记录

```

### 9.1 联网搜索

```

### 9.3 联网搜索：三档链路核对（2026-10-18，只核对不改）

用户要求：「联网搜索现在是这样，不需要改，你看看代码对不对的上就可以了」。

**菜单 ↔ 配置 ↔ 后端，逐层核对：**

| 层 | 位置 | 内容 | 对得上？ |
|---|---|---|---|
| 菜单 | `main/index.ts:3331` radio 子菜单 | 精准搜索（约 10~20 秒）/ 快速搜索（约 2 秒）/ 关闭联网搜索 | ✅ |
| 配置真源 | `persona.yaml` 的 `tools.web_search_mode` | `accurate` / `fast` / `off`，默认 `off` | ✅ |
| 主进程 | `index.ts:1039` `readDeepScalar(['tools','web_search_mode'])` | 落盘 + `config.update` 热更新 | ✅ |
| 大脑读法 | `gateway._web_search_mode()` (L1421) | 兼容老键：`web_search: true` → `fast`，缺省 → `off` | ✅ |
| 后端选择 | `tools.set_search_mode()` / `_web_search()` (L316) | `accurate` 先走 free-search-mcp，`fast` 走 websearch-mcp，失败退回自抓 | ✅ |
| 工具注册 | `gateway._tools()` (L1343) `allow_web=self._web_enabled()` | 关掉时 **web_search/web_fetch 根本不注册** | ✅ |
| 热切换 | `_invalidate_tools()` (L500) | 任何 `config.update` 都清缓存 → 下次生成重建，**不用重启** | ✅ |

逐条结论：**聊天那条路的开关是真的**（不是假开关），三档语义也对得上菜单文案。

**但发现一处对不上（隐私面），记在这里待改：**

```
events.py:70   CAPABILITIES["web_search"] = True   ← 写死 True，从不随模式变
events.py:155  philosophy 事件 needs=("web_search",)
gateway:3847   ctx["search"] = self._event_search if CAPABILITIES.get("web_search") else None
gateway:3910   _event_search() **没有**检查 _web_enabled()
```

也就是说：用户把菜单切到「关闭联网搜索」后，**随机事件（哲学事件）仍可能联网搜索**。
修法（等用户发话，3 行）：

```python
# 方案 A（最小）：_event_search 开头加守卫
if not self._web_enabled():
    return ""

# 方案 B（更彻底）：CAPABILITIES 每次判定时从配置算，而不是写死 True
ctx["search"] = self._event_search if (CAPABILITIES.get("web_search") and self._web_enabled()) else None
```

方案 B 更符合"能力表是唯一开关面板"的原意，也顺手把模块化时 `search` 模块的闸门做出来了。

**打包注意**：`tools/goruntime/websearch-mcp.exe` 与 free-search 的端点/命令
（`tools.free_search_url` / `tools.free_search_cmd`）缺任何一样，就会静默降级成
"自己抓"甚至搜不动 —— 打包后必须实测一次三档。

## 十一、阶段一已落地（2026-10-18）与实现上的两个决定

`
已落地：apps/brain/pet/modules.py + config/persona.yaml 的 modules 段 + gateway 五道闸门
已验证：关掉 voice -> 不建 ASR/TTS 引擎（能力报告变成 mock、大模型=不加载）；开回来复原
`

**决定一：真源放在 persona.yaml 的 modules: 段，不是独立的 config/modules.yaml**

理由：避免第二个配置文件产生双份真相（本项目已因两份实现栽过多次）。
Config 本来就只认 persona.yaml，多一个文件就要多一条加载/热更路径。

**决定二：阶段一闸门只放启动/订阅层**

`
voice     不建引擎
autonomy  不起三个循环
screen    不起截图循环
search    _web_enabled() 里叠加（叠加菜单三档模式）
`

放进 handler 的话，关了还会被调用再拒绝 —— 日志会显得它明明关了还在跑。

**已知坑**：项目自带的 YAML 解析器**不支持流式映射**（{enabled: true} 会被读成字符串），
所以 modules 段必须写块状；ModuleRegistry 对字符串也做了兜底。
