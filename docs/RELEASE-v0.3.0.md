# v0.3.0 — 表情包能用了

**发布日期**：2026-11-07

这一版的主题是**表情包**：从"能发"到"发得对"。另外修了三个真 bug
（免打扰还能触发语音、表情包白名单漏登记、气泡上半部分被裁），
并把表情包的开关统合成了一个模块。

---

## 一、表情包：2272 张入库，72 类细粒度分类

### 导入与压缩

你给了 3.3 GB 的素材包，压缩后 **131 MB**（4%）：

| 类型 | 数量 | 处理方式 |
|---|---|---|
| 静图 | 2173 张 | 最长边 400px + webp(q85) |
| 动图 | 99 个 | gif 转 webp 动图（保留全部帧） |

**动图这一步差点没做成**：第一版"原样保留 gif"，结果 97/102 张被跳过
—— 它们都是 6~10 MB（512×512、80~90 帧）。转成 webp 动图后：

```
1.gif   87 帧  6970KB  ->  436KB（帧数一个不少）
10.gif  80 帧  9451KB  ->  744KB
```

**四个 zip 是冗余的**：三个静图包内容和根目录散图 100% 相同
（抽样 200 条，同名 200、同 sha1 200）。省了 1.2 GB 的解压。

### 分类从 5 类扩到 72 类

> 「现在开始分类，要根据图片的表达信息总结来分类，要细致，
>   比如捣蛋类动图、可爱求安慰等等」
> 「细粒度50+，毕竟表情包本就是为了表达某个情绪想法的建议画面」

按**表达意图**分组：正面情绪 / 负面情绪 / 反应态度 / 行为动作 / 互动社交。

### 两步分类：模型只做它擅长的

72 个选项直接让模型挑等于抽奖（5 类时准确率就不算高，20 类是上限）。
所以：

```
① 让模型用自己的话说这张图表达什么（1~3 个意图关键词）
② 本地拿这些关键词去匹配 72 个类别标签
```

匹配四档从严到松，包括**同义词表**（「想吃东西」→「饿了」）。
实测 18/18 意图词命中正确类别。

### 意图优先于心情

新增 `_INTENT_HINTS`：从**回复内容**判断该配哪类图。

```
「对不起，是我错了」 -> sorry     （不是 sad）
「晚安，好梦」       -> goodnight
「分我一点嘛」       -> ask_money
```

**为什么必须这样**：72 类里有一大批和心情无关的类别（道歉、道谢、讨要、
打招呼、道晚安）。「对不起我错了」的心情可能是 neutral，但它显然该配道歉图。
只看心情的话这些意图**永远发不出图**。

## 二、修了三个真 bug

### ① 免打扰还能触发语音

> 「有bug，现在免打扰还能触发语音」

启动日志揭示了真相：

```
10:59:02.674  免打扰：从 persona.yaml 恢复为「开启」
10:59:03.185  [按住说话] 渲染层已就绪，把开关状态推过去：开   ← 又开了
```

`setPausedInternal` 确实发过「关麦」，但那是**渲染层就绪之前**发的 ——
`webContents.send` 不排队，消息直接丢了。之后 `ptt-config`（推的是配置值）
把闸门重新打开。

**两道防线**：主进程在免打扰时报 `enabled: false` 并补发一次；
sidecar 在 `voice.control` 里直接拒绝（不管上游发什么，我都不听）。

### ② 表情包发了但看不到

主进程的 `parseMessage()` 有一份类型白名单，里面**没有** `pet.sticker`：

```
[brain]  表情包：发了 stickers/shy/s01670.webp
主进程   丢弃无法识别的消息：{"type":"pet.sticker","data":"UklGR…"}
```

**大脑发出了、主进程自己扔了**，而两侧日志各自都"看起来正常"。

### ③ 表情包上半部分被裁

`.bubble` 的入场动画是 `translateY(-6px) scale(0.94)` —— 向上偏 6px。
而气泡是 `position: absolute; bottom: 0` 贴窗口底边，加上
`body { overflow: hidden }`，那 6px 直接被切掉。

改成向下偏（往窗口内部），并把尺寸余量从 8 提到 16。

## 三、表情包为什么"难触发"

> 「你试试不同种类的表情包触发，我现在有些难触发」

用 38 种对话离线测 + 12 轮真实对话测，找到三个原因：

### ① 12 个类别零素材，全退到同一张微笑

害怕、孤单、失望、发呆、苦笑、不赞同、恶作剧、摸摸头、围观助威、
吹嘘、安心、卖惨 —— 这些意图命中后找不到素材，就退回心情类，
而心情类常态是 `smile`。

**修法**：给每个零素材类别配语义相邻的兜底（害怕→震惊、孤单→委屈、
发呆→思考）。踩了一次顺序坑：候选表 `[意图, 心情, 相邻]` 时
`smile` 排在相邻类前面、永远先命中 —— 改成 `[意图, 相邻, 心情]`。

### ② 单独的「？」当触发词

`(("为什么", "怎么会", "真的吗", "？"), "question")` —— 「？」是单字符
触发词，而宠物说话经常带问号。你说「哈哈哈哈哈」，它回「是那串符号
显示成图了吗？」，于是发出一张"疑问"表情包，气氛完全不对。

### ③ 心情映射只有 1 个候选

意图只命中 40%，剩下 60% 全靠心情，而心情映射只有 7 条单映射。
**六成回复的可用类别只有 7 个，其中 neutral 永远只对应 smile。**

改成每种心情 3~6 个候选，并且**随机挑**（不是固定第一个）：

```
neutral -> 微笑 / 好的 / 思考 / 安心 / 同意 / 等待
happy   -> 开心 / 微笑 / 大笑 / 兴奋 / 加油
sad     -> 悲伤 / 哭泣 / 委屈 / 失望 / 疲惫
```

实测 200 条真实回复：**能配到图从 47% 提到 100%**。

### 还修了一个让 1270 张素材沉睡的 bug

`unlabeled()` 原来只判 `caption` 是否为空。于是有一类数据永远处理不到：

```
有 caption（描述有了），但 emotion 为空（没归类）
```

**实测 1270 张卡在这个状态** —— 早期用老提示词标的，72 类上线后没被重跑。
`stickers_for()` 要求有 emotion，它们一条都进不去；而 `unlabeled()` 又认为
"标过了"不再处理。

## 四、other：让宠物自己决定要不要随性发

> 「那你把这些都放进other里面，宠物在不触发表情包中种类的图片后
>   可以选着触发other中的图片，这个由宠物自己决定要不要使用」

1151 张"没有明确类别标签"的图移入 `stickers/other/`。它们里面既有可爱的
表情包（"向Claude看齐"梗图、捧饭碗跪坐的少女），也有烹饪视频截图 ——
**宠物不知道具体是哪张**，所以这一路是"随性"不是"精确匹配"。

实现上**踩了一个坑**：第一版把 other 插进候选列表当普通选项，
实测 200 次挑图 other 占比 **0%** —— 因为 neutral 有 6 个候选且全都有素材，
按顺序查找永远轮不到它。

改成**先掷骰子决定分支**：18% 直接走 other，其余走正常路径。
这样占比可控，和候选数量无关。实测 17~20%。

## 五、模块：表情包统合 + 语音说明写清楚

### 表情包下载与使用合成一个模块

改之前 `stickers` 模块**只管下载**，而发表情包完全不看模块开关 ——
关掉「表情包下载」之后宠物**照样发表情包**，那个开关等于没作用。

现在：

```
stickers            「表情包」    总开关：发表情包 + 归类 + 标注
stickers_download   「表情包下载」 子能力：上网找图
```

**为什么拆两个而不是一个**：风险不同。发表情包是纯本地行为；
上网下载会主动往外发请求并写文件。合成一个的话，你想发表情包就
不得不允许它上网 —— 那是强迫授权。

配置加了迁移：你原来的 `stickers: enabled: true`（当年同意下载）
会正确继承到 `stickers_download`，不会被静默关掉。

### 语音模块说明写清楚

> 「语音模块包含识别用户的话和合成语音吗，如果是的话，
>   语音模块的描述上要写清楚」

查证结果：**两个都管**。`build_voice_pipeline` 一次建 ASR 和 TTS 两个引擎。

原来的说明是「关掉则不建 ASR/TTS 引擎」—— ASR/TTS 是行内缩写，
普通用户看不懂。改成：

> 同时管两件事：① 识别你说的话（语音转文字）② 宠物出声说话（文字转语音）。
> 关掉后它既听不到你说话、也不会出声，只能打字聊

## 六、其他

### 四个宠物大小的探头平移距离分别可调

四个档位的立绘差一倍（150px vs 300px），一个统一值必然顾此失彼。
现在每档独立，默认值 38 / 56 / 64 / 73。

顺带修了"换大小要重启才生效"—— 根因是 `uprightArtRect` 是渲染层
异步上报的，换大小那一刻拿到的还是旧尺寸。

### 新工具：`tools/sticker-status.py`

一条命令看表情包状态：分类进度、每个类别多少张、哪些类别素材太少。

## 测试

| 项 | 结果 |
|---|---|
| 后端自检 | **209 / 209** |
| 主进程 | **563 / 563** |
| 渲染层运行时 | **27 / 27** |

新增断言里比较关键的几条：

- 免打扰中麦克风请求一律被拒（且拦截必须写在 `set_enabled` 之前）
- 表情包白名单里有 `pet.sticker`（防再次"发了但被丢弃"）
- 语音说明必须提到「识别」和「说话」，且不能只写 ASR/TTS 缩写
- 关掉语音模块后 ASR **和** TTS 都必须是 mock（只关一半不算关掉语音）
- other 占比必须 > 0 且 < 40%（防那次 0% 的坑）
- 相邻兜底**必须排在心情前面**（源码断言，防再次写反顺序）

## 升级注意

**表情包会全部重新扫描一次**（约 1 秒）。如果你的 `pet-media/` 里有
手动改过的目录结构，它们会按新规则重新归类。

**表情包下载默认关**。这是主动联网行为，需要你在设置里显式打开。
