# 架构评审（2026-10-14）

> 结论先行：**骨架是好的**——双进程隔离、事件总线、协议门禁、11 道检查这套东西都值得保留。
> 问题集中在四处：**巨石文件、旧实现残留、日志/临时目录失控、协议三副本手工同步**。
> 后续要加功能，先做下面 Top 5，否则每加一个功能都要在 6000 行的 index.ts 里找位置。

## 三、行动路线（Top 5，按"对加功能的影响"排序）

### 1. 拆分主进程 index.ts（收益最大）
按功能域切，建议目标结构：

```
src/main/
├─ index.ts            只剩：main() 按步骤编排（协议→窗口→sidecar→IPC→快捷键），< 200 行
├─ lifecycle/          启动诊断、启动标记、退出协调、日志轮转
├─ ipc/                settings.ts / renderer.ts / chat.ts / windows.ts —— 每个 < 400 行
├─ state.ts            把 ~30 个全局变量收敛成一个 AppState 对象（或按域分 3-4 个小仓库），
│                      读写全走函数，谁改什么一目了然
└─ （已有的 petWindow/petMenu/... 不动）
```
拆法可以**渐进**：每次抽一个域（如设置 IPC），跑全部门禁，绿了再抽下一个。
现有 11 道门禁 + test-main 359 项断言就是安全网，这是做这次重构最大的本钱。

### 2. 渲染层模块化
settings.js / app.js / memory.js 改成 ES module 多文件（构建已有 esbuild，支持打包）。
先按现有 `// ----` 注释分块切：app.js → 气泡定位 / 口型 / 语音 / 状态 / 调试 HUD；
settings.js → 每个标签页一个模块。行为零变化，纯搬家。

### 3. 收敛 Python 记忆层
- `gateway.py:1470` 的 `from .memory import ...` 切到 memory2（只用到 FactExtractor/MemoryConfig，
  搬进 memory2 或单独 facts.py）
- 旧 `memory.py` 归档删除；`memory2.py` 更名 `memory.py`（腾出干净名字）
- vision / embedding 同理收敛命名，删掉 `vision_test.py` 这类生产树里的测试文件（挪 selftest）

### 4. 修日志轮转
「启动时轮转一次」改成「写入时检查大小，超限当场滚动」：log() 里计数，超 20 MB 就
`main.log → main.log.1 → main.log.2`（.2 直接删）。Python 侧同理。半天工作量。

### 5. 临时目录生命周期
- Electron 启动时清扫 `pet-fs-*` 中 mtime 早于本次启动的残留目录
- selftest 启动时清扫 `pet-selftest-mem-*`（try/finally 已有，补异常路径）
- 顺带：`.pnpm-store`、`.tmp-design`、`.ref-pet-source`、`pet-selftest-mem-*` 移出仓库根或加 .gitignore

### 次优先（等 Top 5 做完）
- 协议代码生成：从 protocol.json 生成 index.ts 的类型与 protocol.py 的常量，消灭三副本
- gateway.py / voice.py 拆分（Conversation 类 1,300 行）
- test-main.mjs 按域拆分

## 四、不建议动的
- 双进程 + 环回 WebSocket 架构：隔离与安全设计是对的
- 每窗口独立 preload：最小授权，值得保持
- 11 道门禁 + 359 项主进程断言：重构时它们是安全网，不是负担
