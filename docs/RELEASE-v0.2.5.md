# v0.2.5 — 小说阅读完整了

**发布日期**：2026-11-02

这一版把**小说阅读**补完整：能回看前面读过的章节，书源也修了几个
"读了但读错"的问题。另外修掉两处「联网搜索」假开关。

---

## 一、小说阅读完整了

### 新功能：回看

> 「给它加一个能看过往章节的功能吧，这样方便回去看伏笔和故事精彩描写」

新增 `review_book` 工具，三种用法：

| 传什么 | 得到什么 |
|---|---|
| 只给书名 | **章节目录**（有哪些章、各多少字） |
| `from_chapter` / `to_chapter` | 正文（含两端） |
| `limit_chars` | 每章最多多少字（0 = 全文，上限 4000） |

**只在有目的时用**，不是日常消遣：

> 「宠物正常是不会看的，需要了解一些东西的时候可以适当回看拼接起来，
>   或者由用户说回顾精彩章节什么的。」

所以工具描述里写明了：

> ⚠️ 不要因为闲着就翻旧章节 —— 那会把上下文挤爆，
> 而且用户要的是「你读下去」，不是「你回头看」。

**为什么只读本地不联网**：已经下载的章节就在 `pet-books/<书名>.txt` 里。
重新联网抓有三个问题：慢、书源可能已失效、**站点内容可能改过**
（回看应该看到当初读到的那一版）。

### 修掉：读错书（严重）

原来代码里有个兜底：

```python
title, url = next((b for b in books if query in b[0]), books[0])
```

搜不到匹配就随便拿第一本。实测：让它读《夜玄》，新笔趣阁返回一堆带"玄"字的
无关书，一本都不含「夜玄」，于是落盘的是《让你御兽，你融合斩魄刀？》——
**而日志显示"读了 3 章"，看起来完全正常，只是读错了书。**

现在匹配不上就换源，宁可读不到。

### 修掉：前两章消失

两处代码都硬编码跳过前两章（因为新笔趣阁第 1 章叫「版权信息」）。
但思兔阅读的《天官赐邪》第 1、2 章是正常正文，被一起跳掉了。

现在改成**按内容判断**：

```
空章                          -> 跳过
标题像版权页 + 内容不像正文    -> 跳过（两条都满足才跳）
楔子/序章/引子/前言            -> 一律当正文
其余                          -> 照读
```

重复条目（同一章的两个入口）也会去重。

### 修掉：记忆里是半截话

> 「记忆里面最新一条是没说完话吗」

根因是阅读回调给的是**每章 100 字的摘要**，不是正文。
现在读完整正文（363 字 → 12871 字），并且截断落在句子边界上。

## 二、「联网搜索」两处假开关

> 「联网搜索小黑盒杂谈使用的是联网搜索模块吗，小说阅读用的也是吗」

查这个问题时发现：**设置里关掉「联网搜索」其实没关掉。**

**假开关 ①**：有两个模块注册表实例。设置页切换改的是一个，
而 `_web_enabled()` 读的是另一个 —— 于是"关了还在搜"。

**假开关 ②**：工具清单是懒加载缓存，切换模块时没清，
模型照样能调 `web_search`。

**顺带**：小黑盒杂谈原来没绑 `search` 模块（模块关着时仍被抽中，
抢槽后进去发现搜索被拒，白占一个槽）；自主阅读循环也绕过了联网闸门
（自己造工具清单，不经过 `_tool_list()` 的检查）。

现在：

```
关「联网搜索」  -> 杂谈停 + 小说阅读停 + 工具清单从 9 个缩到 2 个沙箱工具
关「小说阅读」  -> 小说停，杂谈照常
开回来          -> 工具清单完整恢复
```

## 三、底层区别（顺便说明）

这两个功能**不是同一套底层**：

| | 用什么 | 受哪个模块控制 |
|---|---|---|
| 小黑盒杂谈 | `web_search` + `web_fetch`（搜索引擎抓网页） | `search` |
| 小说阅读 | 自己的书源解析（直接抓小说站） | `reading` |

但两者都需要联网，所以关掉「联网搜索」时两个都停。

## 已知限制

· **番茄小说抓不了**：正文接口返回 200 但 0 字节，需要字节跳动 App 级签名。
· **免费书源寿命短**：失效是常态，抓不到会安静地换源，不会打扰你。
· **自签名证书对陌生人无效**：推荐下载**绿色版**（`-portable.zip`）。
